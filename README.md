# SANSAI Hospital Strategy & Plan — ระบบบริหารแผนงาน/โครงการ รพ.สันทราย (v2.6)

Frontend: **Vercel (GitHub)** · Backend: **Google Apps Script (JSON API)** · ฐานข้อมูล: **Google Sheets** · ล็อกอิน: **Gmail + แอดมินอนุมัติก่อนใช้งาน**

```
เบราว์เซอร์ (Vercel, static) ──fetch POST (text/plain)──▶ Apps Script Web App ──▶ Google Sheets / Drive
        │  Google Sign-In (ID token)                           │ ตรวจ ID token กับ Google + ตรวจสิทธิ์จากชีต Users
        └──────────────────────────────────────────────────────┘ ออก session token (ลายเซ็น HMAC, อายุ 12 ชม.)
```

## ใหม่ใน v2.5 — ทบทวนความสอดคล้องของข้อมูล + สถานการณ์หน้างาน + สถานะกำลังทำงาน
**ความสอดคล้องของข้อมูล (ทุกหน้าใช้กติกาเดียวกัน)**
- กิจกรรม "เลยกำหนด" นิยามเดียวทั้งระบบ (กระดานงาน แผนเวลา หมุดหมาย ทีม แจ้งเตือน): ยังไม่เสร็จ + เลยวันสิ้นสุด + ไม่ใช่กิจกรรมที่ "เลื่อน"
- แผนที่ "ส่งสรุปแล้ว/ปิด" ถือว่ากิจกรรมทั้งหมดเสร็จ (ไม่ค้างเป็นเลยกำหนดตลอดไป) ยกเว้นผู้ใช้ตั้งสถานะเอง
- หมุดหมาย "ส่งสรุป" ใช้กติกาเดียวกับหน้า "ค้างส่งสรุป" (พร้อมแสดงเหตุผล)
- หน้างบประมาณ/รายงานผู้บริหาร ใช้ขอบเขตเดียวกับหน้าภาพรวม (เฉพาะแหล่งเงินที่นับใน KPI รพ.) และเลือก "ทุกแหล่งเงิน" ได้
- ทะเบียนที่ไม่ผูกแผน (ประชุม/ทรัพยากร/ความเสี่ยงทั่วไป) แสดงตามปีงบประมาณของ "วันที่" ไม่โผล่ทุกปี

**สถานการณ์ที่ระบบรับมือ**
- เบิกจ่ายเกินงบ → แจ้งเตือนด่วน · ลำดับวันที่เบิกผิด (จ่ายก่อนขออนุมัติ) → ไม่ให้บันทึก · วันจ่ายเป็นอนาคต → เตือน
- วันที่สิ้นสุดก่อนวันเริ่ม / กิจกรรมไม่มีวันที่ → แจ้งเตือนให้แก้ (กระทบแผนเวลา/หมุดหมาย) · ผู้ใช้รออนุมัติสิทธิ์ → แจ้งแอดมิน
- กดบันทึกซ้ำ/เครือข่ายช้า → ไม่เกิดรายการซ้ำ · เปลี่ยนสถานะงานซ้ำระหว่างบันทึก → ไม่ส่งซ้ำ · กิจกรรมที่ยกเลิกแล้วแก้ความคืบหน้าไม่ได้
- ป้องกันการฉีดสูตรเข้าชีต (ข้อความขึ้นต้น `=` `+` `@`) และลิงก์ที่ไม่ใช่ `http(s)` (เช่น `javascript:`) ทั้งตอนบันทึกและตอนแสดง
- ผู้ที่ไม่ใช่แอดมินไม่เห็นอีเมลในหน้าทีม/ประวัติ

**สถานะกำลังทำงาน (UI)**
- แถบโหลดบนสุด + ข้อความ "กำลังประมวลผล…" เมื่อรอเกิน 5 วินาที (Apps Script เริ่มเครื่องช้าครั้งแรก) · โครงร่าง (skeleton) ขณะโหลดหน้า
- ปุ่มทุกตัวที่ทำงานแบบ async (`data-act`) และปุ่มบันทึกในฟอร์ม แสดงตัวหมุน + ปิดการกดซ้ำจนเสร็จ · การ์ดงานแสดงตัวหมุนระหว่างบันทึก
- ฟอร์มตรวจช่องจำเป็นก่อนส่ง (ไฮไลต์ช่อง + ข้อความ) · อ่านข้อมูลล้มเหลวจากเครือข่ายจะลองใหม่อัตโนมัติ 2 ครั้ง (คำสั่งเขียนไม่ลองซ้ำเอง) · แถบแจ้งเมื่อออฟไลน์
- รายงานผู้บริหาร: บางส่วนโหลดไม่สำเร็จยังแสดงที่เหลือพร้อมแจ้งเตือน · กราฟโหลดไม่ได้ → แสดงข้อความแทน ตัวเลขในตารางยังใช้ได้

## ขั้นตอนติดตั้ง (ทำตามลำดับ)

### 1) สร้างฐานข้อมูล + backend
1. สร้าง Google Sheet ใหม่ ตั้งชื่อ เช่น `ฐานข้อมูลแผนงาน รพ.สันทราย`
2. เมนู **Extensions › Apps Script** → ลบโค้ดเดิม แล้ววางเนื้อหา `backend/Code.gs`
3. **Project Settings** › ติ๊ก *Show "appsscript.json" manifest file* → วางเนื้อหา `backend/appsscript.json` ทับ (ตั้งเขตเวลา/สิทธิ์/แบบ Web app ให้)
4. **Project Settings › Script properties** เพิ่มค่าตามตารางด้านล่าง (อย่างน้อย `GOOGLE_CLIENT_ID` และ `ADMIN_EMAILS`)
5. เลือกฟังก์ชัน **`setupSheet`** แล้วกด Run (ครั้งแรกจะขออนุญาตสิทธิ์ — กดอนุญาต) → ดู Execution log ว่าสร้างครบ
6. รัน **`checkConfig`** เพื่อตรวจว่า Script properties ครบ

### 2) สร้าง Google OAuth Client ID (สำหรับปุ่ม Sign in with Google)
1. [Google Cloud Console](https://console.cloud.google.com/) › สร้าง/เลือกโปรเจกต์ › **APIs & Services › OAuth consent screen** (User type: External, กรอกชื่อแอป/อีเมล) แล้วกด **Publish app** (ใช้แค่ขอบเขต email/profile จึงไม่ต้องรอตรวจสอบ ถ้าไม่ publish จะมีเฉพาะ Test users เข้าได้)
2. **Credentials › Create credentials › OAuth client ID** › Application type: **Web application**
3. **Authorized JavaScript origins** ใส่โดเมนที่จะใช้ เช่น `https://ชื่อโปรเจกต์.vercel.app` (และโดเมนจริงของโรงพยาบาลถ้ามี, `http://localhost:3000` สำหรับทดสอบ) — *ไม่ต้องใส่ redirect URI*
4. คัดลอก **Client ID** ไปใส่ทั้ง Script property `GOOGLE_CLIENT_ID` และ `config.js`

### 3) Deploy backend เป็น Web app
**Deploy › New deployment › Web app** — Execute as: **Me** · Who has access: **Anyone** → คัดลอก URL (ลงท้าย `/exec`) ไปใส่ `API_URL` ใน `config.js`
> ทุกครั้งที่แก้ `Code.gs` ให้ **Deploy › Manage deployments › ✎ › Version: New version** (ใช้ deployment เดิม URL จะไม่เปลี่ยน)

### 4) Deploy frontend ขึ้น Vercel
1. แก้ `config.js` (API_URL, GOOGLE_CLIENT_ID) → push ขึ้น GitHub (ใช้ repo เดิม `sansaiplan` ได้ — แทนที่ไฟล์ `index.html` เดิมทั้งหมด)
2. Vercel › **Add New Project** › เลือก repo · Framework Preset = *Other* · Root Directory = ค่าเริ่มต้น (root) · ไม่ต้องใส่ Build Command (ถ้าโปรเจกต์ Vercel เดิมผูกกับ repo นี้อยู่แล้ว แค่ push ก็ deploy ใหม่เอง)
3. เมื่อได้โดเมน ให้กลับไปเพิ่มโดเมนนั้นใน *Authorized JavaScript origins* (ข้อ 2.3)

### 5) เข้าใช้งานครั้งแรก
เปิดเว็บ › Sign in ด้วยอีเมลที่ใส่ใน `ADMIN_EMAILS` → ได้สิทธิ์แอดมินทันที  
ผู้ใช้คนอื่น: Sign in ครั้งแรก = สถานะ **รออนุมัติ** (ระบบส่งอีเมลแจ้งแอดมิน) → แอดมินเข้าเมนู **ผู้ใช้งาน** กด **อนุมัติ** เลือกบทบาท → ผู้ใช้ Sign in ซ้ำเข้าได้ทันที

### 6) (ครั้งเดียว) นำเข้าข้อมูลปีงบ 69 จากชีทเดิม
ตั้ง Script property `PLAN_SHEET_ID` = ID ของชีท "สรุปแผนงาน+โครงการ ปีงบ 69" → รัน **`previewImport`** (ดู Log ก่อน ไม่เขียนข้อมูล) → รัน **`runImport`**  
ตัวนำเข้าจะ: แตกงวดเบิกจ่ายจากสูตรบวก · แปลงหมายเหตุเป็นสถานะ · แปลงวันที่ข้อความเป็นวันที่จริง · ข้ามแถวหัวข้อที่ไม่ใช่แผน · ส่งสิ่งที่อ่านไม่ได้ไปที่เมนู **ข้อมูลรอแก้ไข** (ไม่เดาให้) · ล็อกตัวเอง (`ImportLocked`) กันนำเข้าซ้ำทับข้อมูลที่แก้ในเว็บแล้ว
หลังนำเข้า: เมนู **ข้อมูลหลัก › ผู้รับผิดชอบ** ใส่กลุ่มงาน/อีเมลของแต่ละคน (อีเมลที่ตรงกับบัญชีผู้ใช้จะผูกสิทธิ์ "แก้ได้เฉพาะแผนตนเอง" ให้อัตโนมัติ)

## แนวคิดข้อมูลที่ต่างจากชีทเดิม
* **ไม่มีใครพิมพ์ยอดรวม/คงเหลือ/ร้อยละ/สถานะ** — ระบบคำนวณจากรายการงบ (`BudgetLines`) และการเบิกจ่ายรายครั้ง (`Disbursements`)
* **งบที่ใช้จริง** ไม่นับกิจกรรมสถานะ ยกเลิก/ไม่เบิก/ไม่ใช้งบประมาณ → ส่วนที่เหลือคือ **งบที่ปลดล็อกได้** (ตั้งค่านิยามร้อยละได้ที่ ข้อมูลหลัก › ตั้งค่าระบบ)
* **ค้างส่งสรุปโครงการ** คำนวณอัตโนมัติ (เบิกครบแล้ว / กิจกรรมสุดท้ายเกิน `SummaryGraceDays` วัน / สิ้นปีงบ) แทนแท็บที่ลอกมือ
* **เขตสุขภาพที่ 1** เป็นแหล่งเงินที่ "ไม่นับใน KPI รพ." (เปลี่ยนได้ที่ข้อมูลหลัก › แหล่งเงิน)
* **ยุทธศาสตร์ 4 ระดับ** เป็นตัวเลือกต่อเนื่อง (เลือกพันธกิจแล้วจึงเลือกยุทธศาสตร์ สสจ. ที่เป็นลูก)
* รายงานหน้าตาแบบชีทเดิม: เมนู **รายงาน/ส่งออก** → สร้างแท็บ `รายงาน-<แหล่งเงิน>` (เป็นรายงานที่ระบบสร้าง ไม่ใช่ที่กรอกข้อมูล)

## แก้ปัญหาเบื้องต้น
| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| ปุ่ม Google ไม่ขึ้น / error `origin_mismatch` | ยังไม่ได้เพิ่มโดเมนเว็บใน *Authorized JavaScript origins* |
| "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" / ตอบกลับไม่ถูกต้อง | `API_URL` ผิด หรือ Deploy ไม่ได้ตั้ง *Who has access = Anyone* หรือยังไม่ได้ปล่อย New version หลังแก้โค้ด |
| "Client ID ไม่ตรงกับระบบ" | `GOOGLE_CLIENT_ID` ใน Script properties ไม่ตรงกับใน `config.js` |
| ผู้ใช้อื่นเข้าไม่ได้ ทั้งที่ Sign in ผ่าน | OAuth consent screen ยังเป็น Testing — กด Publish app หรือเพิ่มเป็น Test user |
| อีเมลแจ้งเตือนไม่ถูกส่ง | โควตา `MailApp` (≈100 ฉบับ/วัน บัญชี Gmail ทั่วไป) หรือยังไม่ได้อนุญาตสิทธิ์ส่งอีเมล — ระบบไม่ล้มเมื่อส่งไม่ได้ |
| `setupSheet` เตือนว่าคอลัมน์ไม่ตรง | มีคนสลับ/แก้หัวคอลัมน์ในชีต — คืนค่าตามที่ระบบเตือน (ห้ามสลับตำแหน่งคอลัมน์) |

## ข้อควรทราบด้านความปลอดภัย
* Session token เก็บใน `localStorage` ของเบราว์เซอร์ — ฝั่งหน้าเว็บ escape ข้อความทุกจุดเพื่อกัน XSS; ควรใช้เฉพาะเครื่องที่ไว้ใจได้ และกดออกจากระบบเมื่อใช้เครื่องสาธารณะ
* ไฟล์หลักฐานตั้งค่าเริ่มต้นเป็น "ใครมีลิงก์เปิดดูได้" (เปลี่ยนเป็น `private` ได้ที่ตั้งค่าระบบ) — อย่าแนบเอกสารที่มีข้อมูลส่วนบุคคลของผู้ป่วย
* ยังไม่มีการจำกัดอัตราการเรียก API (rate limit) นอกเหนือจากโควตาของ Google Apps Script
* ล็อกอินด้วย PIN / อีเมล+รหัสผ่าน / ThaiD ของระบบเดิม **ถูกถอดออก** — ใช้ Gmail อย่างเดียวพร้อมแอดมินอนุมัติ
* ไม่ได้ย้ายฟีเจอร์ "บันทึกข้อความ Word" และ "ZIP รูปรายงานผล" ของระบบเดิมมาในรุ่นนี้
